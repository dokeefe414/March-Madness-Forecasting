# v2.5 — Real daily Elo updates from confirmed games without waiting for NCAA CSV releases

## What was wrong

The automatic archive and Pages builds had been running successfully, but all
2027 Elo/model fitting originally used **only** the SportsDataverse
NCAA-derived schedule CSV. At the November 19, 2026 deployment, that source
contained 953 accepted games and ended at **November 18**, even as ESPN
reported more recent `STATUS_FINAL` scores. Earlier v2.4 displayed ESPN
finals, but did **not** allow the rating pipeline to learn from them.

Rebuilding the site daily does not imply Elo updated daily if no new
validated games entered the actual model. This release changes the model's
game input, not just its visible scoreboard.

## New audited game-to-model pipeline

```text
NCAA scored-game schedule ────────────────────────────────┐
                                                          ├─ reconcile date,
ESPN STATUS_FINAL + completed=true ─ identity verified ──┤  pair and scores
      │                                                   ├─ one accepted result per game
      └── same-season source-authored ESPN program IDs    └─ date-frozen game-aware Elo
            (both sides required)                              ├─ team W/L, form, Elo
                   │                                           ├─ retrain research models
                   └─ archived immutable ESPN receipt          └─ rebuild upcoming probabilities
                              │
           next update: preserve even after ESPN rolling lookback
                              │
         NCAA later catches up: detect exact pair/date/score overlap,
         keep NCAA contest ID; never count the original ESPN win twice
```

The implementation is `research/forecast/elo_results.py` and the
`forecast.live` orchestrator. The ESPN candidate detector shares the
battle-tested `forecast.recent_finals.build_finals` logic:
`STATUS_FINAL`, `completed=true`, positive unequal final scores, a single
competition and proper home/away split. Only if *both* ESPN IDs match
the source-authored **season-2027** NCAA↔ESPN membership links does a
new game enter the rating pipeline. Name-only guesses **do not qualify**.
The current ratings source is still the primary NCAA schedule; older
already-confirmed NCAA contests never disappear or get rewritten.

### Defending against duplicate and disputed results

- ESPN match has its own permanent `eventId` and observed source timestamp.
  A source identity must resolve to exactly one currently rated school.
- Each ESPN-only result is keyed by normalized unordered pair and Eastern
  scheduled date. Multiple ESPN IDs for the same team pair and day are
  withheld as ambiguous.
- Compare all NCAA rows for the same pair within ±1 calendar day to
  handle venue designations and UTC/Eastern date drift. Only one identical
  pair of per-team scores counts as the already-existing NCAA game.
  If scores differ or multiple nearby contests make identity uncertain,
  **quarantine the ESPN extra**—do not double-count it or guess.
- A subsequent changed ESPN final is quarantined and reported.
  Previously recorded receipts are not silently rewritten.
- Unsupported or ambiguous team IDs, non-final, tied/zero/invalid scores,
  future results, and incoherent receipts are excluded.
- Source/API failures do not invent games. The runner uses already committed
  ESPN final receipts for previously confirmed scores when the feed is
  temporarily unavailable.
- `web/public/forecasts/espn-final-receipts.json` is written and committed
  by **only the archival workflow** (`--save-espn-receipts`), after the same
  controlled Git rebase/push as immutable prediction snapshots. Website
  rebuilds **read** that file but never write it to the Git repository.
  The receipt file contains only game outcomes and provenance, not a
  rewritten or backfilled before-tipoff prediction.

### What gets updated every successful refresh

1. Every qualifying final receives one game-aware zero-sum Elo update
   for both schools, including opponent strength, home designation, capped
   winning margin and W/L history. Ratings replay deterministically from all
   accepted games on each update; historical NCAA games retain priority.
2. `2027-games.json` contains this **combined, deduplicated source
   history**. Regularized online logistic research, opponent-adjusted
   strength, Kalman-style models, advanced challengers and score research
   all rebuild against the newly accepted games during existing scheduled
   workflows.
3. `upcoming.json` uses the updated source-aligned ratings; scheduled
   pretipoff forecasts are frozen only *before* each actual ESPN-listed
   game start with the existing 15-minute buffer.
4. The current model stream is explicitly versioned
   `source-aware-game-elo-v2-espn-final`. Future frozen first picks carry
   this rating-method tag; prior original snapshots are never changed.
5. The Game Center and Recent Finals show **separate** latest Elo result
   date, NCAA-only release date, ESPN-only Elo additions and independent
   ESPN confirmed-score states.

The nightly/same-evening schedule remains 2:07, 6:07, 9:07, 16:07 and
22:07 Eastern archiving followed by website builds around 2:47, 6:47,
10:17, 17:17 and 22:47 Eastern in the season. It is still **not an
instantaneous after-buzzer service**, and GitHub/ESPN outages can delay
updates. Scores and ratings reflect the most recent successful publication,
not a constantly live server process.

## Scientific integrity and model expectations

**A model that retrains after games does not automatically become more
accurate.** This update makes the evidence available sooner; its impact on
future accuracy must be measured using the immutable, independently settled
**first-published** pregame forecasts on the original timeline. The historical
date-frozen backtests are retrospectively recomputed from a corrected final
corpus, but late-published scores may have been unavailable at a specific
older forecast timestamp. Such reconstructed research is not proof of
actual forward prediction performance.

**Prediction grading remains stricter than Elo ingestion.**
New ESPN-only results do *not* automatically count as right/wrong original
picks. The settlement system still requires: the original pretipoff
Git snapshot, verified fixture/time buffer, explicit ESPN `STATUS_FINAL`
and **matching independent NCAA score** for the precise matched date/team
pair. This avoids inflating reported model performance from a single
unconfirmed provider.

**Limitations:** Some ESPN finals cannot be used promptly if a school
has not yet been identified by a valid 2027 ESPN-provider team ID. Source
conflicts are intentionally withheld. Venue/neutral designations are
still as reported, not separately independently verified. Additional
regular-season results may temporarily favor or hurt the predictor.

## Source and audit fields

`web/public/current/2027.json.sourceReconciliation` reports:

- `ncaaAcceptedGames` — still-recorded NCAA results
- `ratedEspnOnlyFinals` — uniquely ESPN-confirmed, ID-verified results
  that are *not yet* in NCAA scores
- `totalRatedGames`, `espnFinalsObservedThisRun`
- `persistedEspnFinalReceipts`
- `ncaaLastGameDate`, `espnOnlyLastGameDate`
- `rejectedOrReconciled` — duplicate, ambiguous, invalid or conflicting
  game counts
- `sourceWarnings` — optional API outage days or rejected source.

`current/refresh-status.json` now exposes last NCAA date separately.
`current/recent-finals.json` adds `eloRatingInputConfirmed` for each
displayed ESPN final while retaining `ncaaRatingInputConfirmed`.
`ratingRetrievedAtUtc` remains the snapshot consistency key.


For hermetic offline replay, `forecast.live` supports
`--input fixtures.csv --skip-espn` or explicit
`--espn-scoreboards-json fixtures.json`. Production `--save-espn-receipts`
is reserved for the archive workflow. The first post-merge deployment
must be verified by *actual* Action logs: positive ESPN-only games,
last accepted date, rating changes, nightly model retrain, successful
Games build, and successful Pages publish.

To recover from an ESPN outage, retry the scheduled archive and rebuild
only after the data source is available. Already committed final receipts
remain usable without editing historical pretipoff forecasts.
